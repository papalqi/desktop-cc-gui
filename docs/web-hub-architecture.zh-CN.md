# DevCloud 网页与会话管理

浏览器 → DevCloud Hub → 执行机器的 CC GUI → 本地 AI / 文件 / Git / 终端。

远程入口为 https://arashishader.devcloud.woa.com/CCGUI。Hub 源码在相邻的 `ccgui-relay` 仓库，运行目录为 DevCloud 的 `/data/workspace/ccgui-relay`，Bun 监听 8787。网页构建资源直接由 Hub 的 `web/` 提供，不再依赖 PC5。

## 数据与能力归属

- Hub 的 `data/hub.db` 保存远程会话目录、置顶、标题、归档、模型/effort/provider 偏好、工作区分组/排序、网页设置、完整历史消息、事件日志和搜索索引。
- 数据主键包含机器名、引擎、原生会话 ID。已有本地会话与归档首先只读导入；本地新增会话继续同步，远程修改的管理字段由 Hub 保持。本地 CLI 转录本保留原位置与格式。
- 执行端保留本地 UI、数据库、引擎、插件与文件操作能力。文件/Git/终端、安装与配置本机引擎，以及任务启动/停止经 Hub 路由到选中的执行端。本地使用能力不因网页迁移被关闭。
- 每台机器有一个独立于浏览器的观察/RPC 连接。浏览器关闭、刷新或切换不会关闭该连接，也不会终止 AI 任务。重启 Hub 只重连控制通道；任务进程仍由执行端持有。
- 已导入且事件完整的运行中会话直接读取 Hub 历史，原生转录本在后台核对；翻旧页不重复拉取整段历史。首次导入或事件存在缺口时仍等待补齐。
- 网页的机器身份保存在页面内和地址栏 `machine` 参数中，WebSocket、文件请求和本机标签持久化使用同一身份。共享 cookie 只为新页面提供默认值；多个标签互不切换。插件资源使用 `/m/<机器>/plugin-asset/...` 路径，使相对依赖也保持机器归属。
- Hub 的事件插入游标与原生回合 `seq` 分开。补入旧事件、修正原生转录本时增加 `historyEpoch`；网页带版本请求增量，版本失效后重载快照，再合并同版本的实时事件。已结束但仍有缺口的回合继续显示未完整，直到日志连续或完整原生转录本覆盖该回合。
- 原生转录本已覆盖结束回合时，Hub 从 SQLite 按页读取历史，不再重建这些回合的事件投影。图片、文件等无需文本改写的 HTTP 响应在收到响应头后直接流式转发。
- 已同步的会话可离线浏览、搜索及修改管理状态；任务发送、本地文件操作和需要本机环境的功能在离线时明确失败。Hub 不自动重放可能已经送达的提示词。

## 远程命令面

浏览器里的 `invoke("命令")` 由执行端 `src-tauri/src/web/dispatch.rs` 转到和桌面 Tauri 相同的函数。对齐由 `dispatch::dispatch_parity_test::frontend_invokes_are_routed_or_explicitly_desktop_only` 在测试时读 `src/` 与 `packages/` 的源码：每个静态 `invoke("命令")` 必须出现在分派分支里，或者写进带原因的桌面专属表。桌面专属调用点用 `isWeb` 改成明确的空操作或拒绝，网页不再发出这些命令。`read_font_file` 已接入分派，且不按工作区收口：已批准的浏览器本来就有执行端级控制，字体校验只是类型守卫（魔数与 64MB 上限），不是权限边界。带密钥的设置（provider 密钥、pi 系列密钥、models 配置）经这条中转连接传递，与今天的 `upsert_provider` 相同。执行端对同一个未知命令每个进程只记一条 error。网页按已解析的目标机器和命令记住 `unknown command`：同一条连接不再发给这台机器，另一台机器仍会发送；桥重新连上这台机器，或 hello 报了不同的执行端版本，就清掉这台机器的记录。`get_run_delivery` 与 `close_unreceived_run` 由 Hub 的 `queryMachine` 回答，不进执行端分派。插件 `bridgeInvoke(command, args)` 的命令名是运行时字符串，静态扫描看不到，测试只锁住这个调用形状。

AI 通过登录后的 `/_relay/api` 发现 HTTP 接口与 `/commands` 参数契约；`/machines/<name>/invoke` 复用既有命令查询工作区、会话、消息、文件与 Git，或开始/继续会话、回答提问及中断回合。`/machines/<name>/runs/<runId>` 持久化查询投递和回复，支持有界等待，超时不重放提示词。这些操作接口仅需更新 Hub，不要求升级执行端。诊断接口另提供中转/观察连接、待处理 RPC、历史完整性、操作结果及执行端状态；显式 POST 可同步目录或指定历史。执行端提供 `/api/debug` 和既有 RPC 中的新 `debug_snapshot`，沿用桥接令牌与设备审批。接口契约和调用示例见 [AI 操作与调试 API](ai-debug-api.zh-CN.md)。

运行诊断日志独立保存到 Hub 的 `data/logs.db` 和执行端应用目录的 `diagnostics/logs.db`，包括性能、错误、异常与生命周期；按有界容量保留，沿用原鉴权提供筛选和 NDJSON 导出。执行端升级后在 hello 声明 `debug_logs`，Hub 实时保存日志事件并按独立持久化游标补拉，离线继续读取缓存。日志游标与会话历史游标分离，采集错误与耗时不保存对话增量或工具结果。

## 现有协议兼容

### 只保存远端会话的实现状态

新路径已接入源码，生产四台执行端截至 2026-10-15 00:36 仍为 1.1.3，使用下述兼容路径。机器同时声明 `journal` 和 `session_origin` 时，Hub 只持久保存 `origin=hub` 的目录与未归档正文；本地目录短暂保存在内存，本地和归档正文在线转发读取，不写消息、事件或搜索索引。目录和搜索支持 `scope=remote|all`，来源字段随快照与实时事件返回，来源切换后网页重载快照。

新版远端历史直接复制执行端规范页，不再经过 Hub 的原生转录本修复。完整页覆盖结束回合后清理其事件，保留投递台账；归档先由执行端成功执行，再清理 Hub 正文。纳入远端时发送确认先返回，来源标记和完整导入在后台完成。存量数据库迁移尚未执行：只读分类报告、副本核对与独立候选库工具见 Hub 的 `HUB.md`，不能把源码支持当作生产数据已迁移。

沿用原执行端的 relay `open/data/close` 封装和 WebSocket `invoke/response/event` 协议。本次服务器迁移无需重新构建或重启现有执行程序。Hub 在保存事件后向网页广播，通过 `load_session_events` 补发遗漏事件；支持原生日志的执行端可补齐 Hub 断连期间的记录，旧执行端同步原生转录本。

新网页连接带 `hub=1`，读取 Hub 的消息和日志游标。迁移前已打开的网页暂时保持原生历史读取和原生游标，刷新后切换到 Hub。桌面和局域网直连仍走原本的本地接口。

需要升级执行端的下一阶段（机器身份与令牌、控制/大块分离的专用通道、执行端为准的会话日志、投递查询、空闲自更新）见设计稿 [Agent Link v1](agent-link-v1.zh-CN.md)。

Grok 原生记录可能没有时间戳。执行端对没有历史锚点的首轮仅在提示词唯一匹配时替换原生回合，避免把首轮再次追加到后续回合末尾。Hub 导入旧执行端历史时，仅对没有历史锚点、开始时间不晚于会话创建时间且明确已结束的远程回合进行修复：与更早的无时间戳回合逐条核对角色、正文、工具参数与已有结果，唯一匹配后将包含完整工具结果的副本放回原位置，重排分页序号并更新历史版本。重复提示词有歧义、内容不同或仍在运行时保留原记录；本地转录本不改写。

历史版本及机器路由修复需要同时更新 Hub 与网页资源，现有执行端协议保持兼容。原生 HTTP 取消修复在执行端升级后生效：Hub 发出的 `close` 会取消已派发的本机 HTTP 请求，控制连接退出也会取消转发任务并结束写入，不影响独立的 AI 任务进程。

历史导入逐页进行，分页完整到达后才提交消息快照；不截断正文或工具结果。Base64 封装的执行端响应使用 128 MiB 单帧上限，导入每页最多 20 条，兼顾原生中继内部 WebSocket 的帧限制，避免大页关闭机器或历史读取连接。不能完整同步的记录保留错误和待同步状态。

大页失败后逐次缩小至单条；旧执行端仍无法传输单条大工具结果时，已停止的本地 Codex 会话通过既有文件接口分块读取转录本，由 Hub 按源码中的 Codex 消息格式恢复正文、思考、图片、命令/MCP 结果和逐文件差异。文件授权与 64 MiB 上限继续由执行端执行，大小不符或 JSON 不完整不提交。失败记录单独延后重试，不阻塞其余导入。

## 更新与验证

`pnpm build` 生成网页资源；Hub 仓库运行 `bun test`。服务器部署前备份实际运行源码及现有数据，核对源文件未被他人修改、只停止已确认的 Hub PID；登录票与 `data/` 保留。执行机器、HAPI Hub、AI 子进程均不随本次部署重启。

部署后核对四台机器连接、迁移数量、网页与资源、消息读写/搜索、持久化管理状态，以及迁移前后的活动 run ID。回滚只恢复 Hub 源码和网页资源，不删除新数据库或触碰本地转录本。

参考 HAPI 的 `hub/README.md`（Hub 的 SQLite 持久化、RPC 路由、独立网页发布）及 `cli/README.md` 的 Session lifecycle invariants（本地使用与远程控制可并存）。本项目沿用现有 CC GUI 协议，没有引入 HAPI 的客户端依赖。
